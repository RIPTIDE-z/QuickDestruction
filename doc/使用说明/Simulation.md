# Simulation - 模拟烘焙

把选中的资产放在一起进行刚体模拟：
- 用驱动给碎块初速度，逐帧烘焙成关键帧；
- 烘焙后碎块移出刚体世界，动画完全由关键帧驱动，可以随意拖动时间轴、渲染或继续编辑。

## 面板

```text
模拟烘焙                                   [预设]
  Cube: 120 块碎块
  状态      ⚠ 已过期
            驱动已改动                      过期原因另起一行
  设置在上次烘焙后改过                       面板值与上次实际使用的不同时出现
  2 个资产与 3 个其他刚体一起参与             这次烘焙会碰到什么; 没有其他刚体时只写资产数
  1 个其他资产会临时移出刚体世界              有其他资产在刚体世界里时出现
  建议每帧子步: 34                           建议值比设定值高时出现
  [        烘焙模拟        ]
  [        重置模拟        ]
  ▾ 帧范围      使用场景帧范围, 起始帧, 结束帧
  ▸ 求解        质量, 每帧子步, 求解迭代, 时间缩放 (默认收起)
```

## 参数

| 参数 | 字段 | 默认 / 范围 | 含义 |
| --- | --- | --- | --- |
| 使用场景帧范围 | `use_scene_range` | 开 | 从场景的起始帧烘焙到结束帧；关闭后用下面两项 |
| 起始帧 | `frame_start` | 1 | 碎块在这一帧处于静止姿态 |
| 结束帧 | `frame_end` | 120 | 必须晚于起始帧 |
| 质量 | `quality` | 预览 | 预览按下面设定的子步烘焙；终稿在建议值更高时把子步提高到建议值，上限 200，被截断时在报告里说明 |
| 每帧子步 | `substeps` | 10 / 1–200 | 步数越多，快速或很薄的碎块越不容易相互穿过，耗时也越长 |
| 求解迭代 | `solver_iterations` | 10 / 1–100 | 越多，堆叠的碎块越稳定 |
| 时间缩放 | `time_scale` | 1.0 / 0.01–10 | 小于 1 为慢动作；驱动的速度仍按模拟时间的每秒计算，慢动作下碎块看起来更慢，但物理上一致 |

## 一次烘焙的过程

```mermaid
sequenceDiagram
    participant U as 用户
    participant S as 模拟烘焙
    participant B as 场景
    U->>S: 烘焙模拟
    S->>B: 检查: 物理已应用且输入未变, 缓存未烘焙, 碎块没有外来动画, 结束帧晚于起始帧
    S->>S: 读取驱动, 编译每块碎块的计划
    S->>B: 记下要改动的一切; 其他资产的碎块临时移出刚体世界
    S->>B: 碎块回到静止姿态, 写入交接关键帧, 加入刚体世界
    loop 每一帧
        S->>B: 推进一帧, 到期的再起动, 采样位置与朝向
    end
    S->>B: 写成逐帧关键帧, 换上新动作, 删除旧成果
    S->>B: 碎块移出刚体世界, 恢复世界设置与其他资产, 回到原来的帧
```

- **会话**：一次烘焙是一个**场景会话**，会话的参与者如下：
  - 选中的资产；
  - 刚体世界里其他不属于任何资产的刚体，例如自己放的地面、障碍物。它们照常参与碰撞，属性不被修改，但会随场景一起被推进；
  - 其他资产的碎块不参与：期间临时移出刚体世界，结束后放回。
- **起动方式**：碎块的初速度靠"动画交接"给出。
  - 起动帧 T 时碎块仍在原位，由动画控制；
  - 从 T 到 T+1，动画让它按目标速度移动一个模拟步；
  - T+2 起交还物理模拟，Bullet 保留这一步推算出的速度与角速度；
  - 已经在运动的碎块被后来的驱动波及时，在推进途中从它当前的位置再交接一次：新的速度是**当时的速度加上事件的速度**（当前速度取上一帧到这一帧的平均值），所以自由下落的碎块被推一下后继续下落；连续两帧的事件也都生效。
- **不动的碎块**：锚定的碎块，以及始终没被驱动波及的冻结碎块，按被动刚体参与。它们同样不可撞动，但模拟开销更小，也不带动画。
- **烘焙结果**：每个资产一个动作 `QD_Sim_<资产名>`，每块动过的碎块一个槽位，逐帧线性关键帧，不做精简。整段没动的碎块不写关键帧，停在静止姿态。
- **记录**：资产上记下会话标识与当时的物理修订号；场景上记下会话的参与者、驱动、环境刚体与场景设置的签名。面板状态据此判断是否过期。

## 子步建议

建议值是启发式：

```text
建议子步数 = 向上取整(2 × 计划里的最大速度 × 每帧的模拟秒 ÷ 碎块厚度的 5% 分位数)
```

- **碎块厚度**：碎块局部包围盒最小的一边，乘缩放。
- **局限**：忽略比 5% 分位更薄的碎块；没有计入碰撞时的相对速度、重力加速与旋转扫掠。它不构成防穿透的保证。
- **用法**：面板在建议值比设定值高时提示。把 **质量** 设为 **终稿**，烘焙时自动采用；也可以自己把 **每帧子步** 调高。状态判定拿面板上的设定值与记录比较，终稿提高后的实际子步不会让状态误报"设置改过"。

## 起动被挡住

交接的那一帧碎块由动画推动，而 Blender 里动画控制的刚体与被动刚体、与另一块动画刚体之间没有碰撞：它会径直穿进邻块。下一帧交还给模拟时，求解器把重叠的两块顶开，顶开的速度只取决于穿进去的深度与子步数，和材质、质量无关，表现为碎块向外飞一帧，然后以比爆炸速度更快的速度反向飞出。

所以起动之前，插件先判断这次位移会不会穿进**推不动的物体**，穿进去就改写起动速度：

| 挡路的物体 | 说明 |
| --- | --- |
| 冻结的碎块 | 没被驱动波及的，以及起动时间晚于这次的 |
| 锚定的碎块 | 始终不动 |
| 环境里的被动刚体 | 例如地面；带动画或开了"动画"开关的不算 |
| 同一帧起动的冻结碎块 | 与起动者一起移动，按相对速度判断 |

- **怎么改**：去掉速度里朝向墙面的分量，沿墙面的分量保留，所以贴着邻块侧面斜着飞的碎块会滑着飞出；贴紧墙、没有路可走的碎块不动，等同于撞上推不动的墙后停住。墙角处最多滑动三轮，仍被挡住就按能走的比例缩减。
- **不算挡路的**：休眠与自由的碎块是动态刚体，被推动时有正常的动量传递，不受影响。已经起动过的冻结碎块位置要推进后才知道，不参与判断。
- **报告**：有起动被改写时，烘焙报告末尾写明次数。次数很多、而你想让撞击传下去，把物理设置的受击前状态改成**休眠**。
- **耗时**：判断在烘焙开始前一次完成，见下文[耗时](#耗时)。

## 弹体飞行动画

弹道驱动带子物体（例如一个子弹网格）时，烘焙会给它写飞行动画，写在 `QD_Flight_<驱动名>` 里，随烘焙的写前快照一起提交与撤回。

- 发射帧之前停在原位，之后按弹速沿路径飞行，停在嵌入点；一发子弹同时打几个资产时取飞得最远的那个资产。
- 复位在场景里没有任何模拟成果之后，会删除飞行动作并把子物体放回原位。
- 弹体只是动画，不参与碰撞。

## 取消与失败

- **按 Esc 取消**：只在帧与帧之间生效，单帧的推进不能打断。取消后场景回到烘焙之前，上一次的烘焙成果保留不变。
- **运行中的限制**：烘焙进行时只放行视图的旋转、平移与缩放，其他输入被拦下；脚本再次调用烘焙，或调用物理设置的应用、移除与设为静止姿态，都会因"已有模拟正在运行"而被拒绝。
- **失败时**：任何阶段失败都与取消一样恢复场景，旧成果保留，错误按"烘焙模拟失败：原因"报告。
- **外部中断**：载入其他文件或停用插件时，正在运行的烘焙会被取消；停用插件时场景同样回到烘焙之前。

## 重置模拟

删除所选资产的烘焙成果，碎块回到静止姿态，资产上的模拟记录一并清除。重置是一步普通操作，可以用 **Ctrl+Z** 撤销。它与"取消"不同：取消保留上一次的成果，重置删除它。

## 状态

| 状态 | 条件 |
| --- | --- |
| 未完成 | 没有烘焙成果，或成果动作已被删除 |
| 已过期 | 物理已过期；烘焙后又应用过物理；同一会话的另一个资产变了、不在了、被复位，或单独重新烘焙过；驱动改动了；场景里其他刚体改动了；帧率、单位或重力改动了；场景里找不到会话记录 |
| 输入未变 | 以上都没有发生 |

## 耗时

实测环境为 Blender 5.2.2，场景是边长 4 的立方体，带随机种子、不递归。爆炸驱动约波及一半碎块，冻结方式，有重力，烘焙 60 帧，每帧 10 子步：

| 碎块数 | 切割 | 应用物理 | 起动判断 | 烘焙（含起动判断） | 每帧 |
| --- | --- | --- | --- | --- | --- |
| 99 | 0.15 s | 0.01 s | 0.3 s | 1.6 s | 27 ms |
| 282 | 0.49 s | 0.04 s | 1.5 s | 6.9 s | 115 ms |
| 901 | 2.22 s | 0.17 s | 5.8 s | 22.9 s | 381 ms |

- **耗时去向**：以 Bullet 的推进为主；起动判断随被波及的碎块数增长，901 块约占四分之一，之后的 17 秒是逐帧推进。
- **起动判断的代价**：加入判断之前，同一场景 901 块烘焙 16.2 s。多出来的 6 秒换来的是不再出现反向高速弹出。
- **界面**：烘焙开始时先做起动判断，大场景里点下按钮后进度条要隔几秒才开始动。
- **预览**：可以先把 **每帧子步** 调低，满意后再调回去烘焙成品。
- **复测**：开发时用 `scripts/bench_pipeline.py` 复测这组数据。

## 阶段 API

```python
import bpy

from bl_ext.user_default.quick_destruction.common import asset
from bl_ext.user_default.quick_destruction.tools.Simulation.api import bake, reset

roots = asset.resolve(bpy.context.selected_objects)
result = bake(bpy.context, roots, {"substeps": 20})
print(result.frames, result.moved, result.rehandoffs, result.seconds)
```

| 函数 | 说明 |
| --- | --- |
| `bake(context, roots, config)` | 同步烘焙到底，返回 `SimulationResult(run_id, frames, shards, moved, rehandoffs, clamped, blocked, frozen, excluded, substeps, raised, suggested, capped, seconds)`；失败时场景回到烘焙之前 |
| `bake_steps(context, roots, config)` | 生成器，每推进一帧产出一次 `Progress(done, total)`，返回值是 `SimulationResult`；中途调用 `close()` 即取消并恢复场景；调用方负责运行锁 |
| `reset(context, roots)` | 删除烘焙成果，返回处理的碎块数 |

| 字段 | 含义 |
| --- | --- |
| `clamped` | 早于"起始帧之后第一帧"而被推迟的起动帧个数 |
| `blocked` | 起动速度因被挡住而改写的次数 |
| `frozen` | 整段冻结不动的碎块数：没有被任何驱动波及的冻结碎块 |
| `excluded` | 被区域排除在模拟之外的碎块数 |
| `substeps` | 实际使用的每帧子步数 |
| `raised` | 终稿质量把子步提高到了建议值 |
| `suggested`、`capped` | 终稿质量下的子步建议值，以及它是否被上限 200 截断 |

`clamped`、`blocked`、子步被提高与被截断都会写进烘焙报告。

## 边界

- 碎块带有不是本插件建立的动画时拒绝烘焙，因为交接需要独占碎块的动画。
- 碎块有父级时拒绝烘焙：关键帧写在碎块自己的变换通道里，刚体也按世界姿态推进，有父级时两者对不上。
- 阶段 API 直接接收资产根集合时同样核对：资产被复制（两个集合共用标识）或格式未知时拒绝。
- 只追踪经过插件的改动；在 Blender 自带面板里手动改刚体属性，不会让状态变为已过期。
- 要相互碰撞的资产必须一起烘焙；已经烘焙并移出刚体世界的资产，不再参与之后的碰撞。
- 高速物体可能穿过薄的碎块：Blender 的刚体系统没有开放连续碰撞检测，可以提高每帧子步缓解。
- 起动受阻只在起动的那一帧判断；起动之后的碰撞完全由 Bullet 求解。判断用碎块的网格，不是它的碰撞形状：环境刚体设成盒子或球体时，两者略有出入。
- 休眠与自由的碎块之间同一帧起动时，彼此是动画刚体，也会互相穿进去；速度差越大，穿得越深，反向的修正也越大。
